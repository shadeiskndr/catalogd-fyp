# AGENTS.md

Guidance for coding agents working in this repository.

`Catalogd` — a social cataloguing app for video games (final year project). Next.js 16 (App Router) + React 19, self-hosted Convex backend, Bun, Tailwind v4, Biome. Game data comes from the RAWG API, proxied through Convex.

## Commands

```bash
bun run dev            # Next dev + `convex dev` together — use this, not dev:next alone
bun run check          # biome check --write .  (lint + format + safe fixes) — the main gate
bun run doctor         # react-doctor: React/Next health, perf, a11y, bundle, dead code
bun run test:e2e       # Playwright end-to-end suite (starts/reuses the dev server)
bun run typecheck      # tsc --noEmit (TS 7 native; `next build` also type-checks)
bun run build          # next build
```

**Playwright is the only test framework here, and it is end-to-end only** — there are no unit tests. "Verified" means `bun run check`, `bun run typecheck`, `bun run doctor` (100/100), a successful `bun run build`, `bun run test:e2e`, and — for anything touching data flow — clicking through the affected pages in a browser with the dev console open (Cache Components reports non-instant routes there).

The suite lives in `e2e/` and runs against the real Convex deployment and the real RAWG API, so it needs a working `.env.local` and network. `e2e/auth.setup.ts` signs a throwaway account in (creating it on first run) and saves `storageState` to the gitignored `e2e/.auth/user.json`; override the credentials with `E2E_EMAIL` / `E2E_PASSWORD`. `expect` timeouts are deliberately generous (20s) because a cold `next dev` compiles each route on first hit and will otherwise flake.

`bunx convex dev` (or a deploy) must run after any change under `convex/`: the frontend calls the *deployed* functions, so a renamed module (`api.lists` vs `api.gameLists`) breaks at runtime until it is pushed, even though the build passes.

A fresh deployment starts with an empty catalogue. The crons in `convex/crons.ts` fill it, but to seed it now:

```bash
bunx convex run ingest:refreshGenres '{}'          # genres table (needed before genre lists warm)
bunx convex run ingest:warmHotLists '{}'           # popular/new-releases/upcoming/featured
bunx convex run ingest:warmGenreLists '{}'         # one page per genre
bunx convex run ingest:backfillReferencedGames '{}' # games referenced by existing reviews/library/wishlist
```

Until a list key has been ingested, the first request for it blocks on RAWG once and then is on disk.

## Conventions

- **Source files carry no comments.** `bun run strip-comments:write` enforces this across tracked `.ts/.tsx/.js/.jsx`; it keeps only directives (`biome-ignore`, `react-doctor-disable-next-line`, `@ts-expect-error`, …), legal headers, and `TODO/FIXME/HACK/@deprecated`. Write self-explanatory code instead. Config files are the exception and *are* documented in prose.
- **File names are kebab-case, everywhere, including route segments** (`app/(main)/new-releases/`, `components/review-card.tsx`). No `PascalCase.tsx`, no `camelCase.ts`. Components inside are still `PascalCase` identifiers; hooks are `useThing` in `hooks/use-thing.ts`. **`convex/` is the one exception, and it is enforced by the server**: a Convex module path may only contain alphanumerics, underscores and periods, so a hyphenated file there fails the push with `InvalidConfig: … is not a valid path to a Convex module`. Shared code that both sides need therefore lives in `lib/` and is imported from `convex/` with the `@/*` alias (`lib/game-types.ts`, `lib/rawg-image-path.ts`) — the Convex bundler resolves it.
- **react-doctor scores 100 and `doctor.config.jsonc` only covers deslop's dead-code blind spots** (`unused-file` / `unused-export` over `convex/**` and the vendored registry). Every other intentional violation is an inline `react-doctor-disable-next-line react-doctor/<rule>` placed immediately above the *reported node* (the attribute or the call, not the enclosing statement), with the reason in a plain comment above it — don't add rule entries to the config.
- **Convex lint rules live in `biome-plugins/*.grit`**, ported from `@convex-dev/eslint-plugin` and registered in `biome.json` under `overrides` for `convex/**`. Don't install the upstream package: Biome can't load ESLint plugins, and `typescript-eslint` rejects TypeScript 7. GritQL is syntax-only, has no autofix, and **plugin diagnostics cannot be suppressed** — `biome-ignore` does not apply to them, so the code has to satisfy the rule (see `convex/lists.ts`, which branches on the list literal so `db.delete` gets a string table name).
- Biome: 100 cols, 2-space indent, double quotes, semicolons. `useSortedClasses` auto-sorts Tailwind classes in `className`/`clsx`/`cva`/`cn`/`twMerge`.
- **The `react` and `next` lint domains are on at `"all"`, with no path-based overrides** — `components/ui/**` is held to the same gates as first-party code. Intentional violations are inline `biome-ignore` comments with a reason, never a new `overrides` entry. Three consequences worth knowing:
  - a component file may not export non-components, so `cva` variants live in sibling `*-variants.ts` modules and contexts/hooks in `*-context.ts` (`button-variants.ts`, `sidebar-context.ts`, `form-context.ts`, `theme-context.ts`, `color-context.ts`);
  - JSX props may not take inline functions — hoist to `useCallback`, or push the binding into a child component when it closes over a `.map` item (`GameCommandItem`, `ColorThemeItem`, `ChatMessageItem` exist for exactly this);
  - `noLeakedRender` rejects `{value && <JSX/>}` unless the left side is provably boolean, so conditional JSX is written `{cond ? <JSX/> : null}`.
- **Biome honours `biome-ignore` only on the immediately preceding line**, so it and a `react-doctor-disable-next-line` can't both sit above the same line. When they collide, put the `biome-ignore` above the JSX element and the `react-doctor-disable-next-line` above the offending attribute (see `components/ui/item.tsx`).
- `tsconfig.json` is maximally strict: `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noPropertyAccessFromIndexSignature`, `verbatimModuleSyntax`, `erasableSyntaxOnly`. Two patterns follow from it — `process.env["NAME"]` (never dot access), and `{...(value === undefined ? {} : { value })}` when forwarding an optional prop that the target types as non-`undefined`.
- Commits are gitmoji + conventional: `✨ feat:`, `🐛 fix:`, `♻️ refactor:`, `🔧 chore:`, `⬆️ chore:`.
- **Commit straight to `main`.** Solo repo, no PR review flow — don't create feature branches, not even for dependency bumps.
- Imports use the `@/*` alias rooted at the repo.
- Pre-commit hook runs `biome check --staged` + `react-doctor --staged`; don't bypass with `--no-verify`.

### Design system

- **`app/(main)/layout.tsx` owns the page container** (`mx-auto w-full max-w-7xl px-4 md:px-6`). Route files start with `<PageHeader>` and their content as siblings — they do **not** add their own padding, max-width or `<h1>`. That shared axis is the whole point: before it, `/reviews`, `/write-review` and `/chat` each centred their content while the heading sat at the far left.
- **One page header per route.** `components/layout/page-header.tsx` renders the route's only `<h1>` plus an optional description and an actions slot; `section-header.tsx` renders the `<h2>` + "view all" link used for dashboard sections. The topbar breadcrumb is derived from the pathname, so a page heading that just repeats the nav label needs a description to earn its space.
- **Motion pulls from three curve tokens**, defined in `app/globals.css` `@theme inline`: `ease-out-strong` for enter/exit, `ease-in-out-strong` for on-screen movement, `ease-drawer` for sheet-like panels. The built-in CSS easings are too weak to read as intentional. UI transitions stay under 300ms (hover/press 150ms, cards 200ms, image zoom 500ms since it is decorative).
- **Hover motion is gated behind the `hover-hover` variant** (`@media (hover: hover) and (pointer: fine)`, declared in `globals.css`). Touch devices fire `:hover` on tap and then keep it stuck, so `hover-hover:hover:-translate-y-1` is correct and a bare `hover:` on a transform is not. Pressable elements get `active:scale-[0.97]`–`active:scale-90` instead, which works on both.
- **Every list has a real empty state.** Use `components/ui/empty.tsx` with `className="flex-none border"` — without `flex-none` its base `flex-1` stretches the dashed box to the full viewport height. Pair it with a CTA that names the next step (`Browse popular games`, `Write the first review`).
- **Loading states are skeletons shaped like the content**, not a centred spinner: `GameGridSkeleton` for game grids, per-page skeletons elsewhere. RAWG's `games?search=` endpoint takes 7–8s uncached, so the command palette shows skeleton rows rather than a spinner.
- **Dates are formatted with `lib/format.ts`, never `toLocaleDateString()`.** `formatReleaseDate`/`formatReleaseYear`/`formatTimestamp` parse the `YYYY-MM-DD` string directly and emit a fixed `Mon D, YYYY`, so a server component and the browser cannot disagree. `Intl` in render is also a react-doctor violation (`no-locale-format-in-render`) — if you genuinely need the viewer's locale, format inside a `useEffect` (`components/chat/chat-message.tsx`).
- **Route transitions are CSS, keyed on the pathname** (`components/layout/route-transition.tsx` + the `.route-enter` rule in `globals.css`). React's `<ViewTransition>` is not an option here: it needs React's experimental channel, and this app is on stable 19. The animation starts at `opacity: 0.55`, never 0 — Cache Components exists to paint the shell in ~15ms and fading from transparent hands that back. Same reasoning as "never animate from `scale(0)`". 180ms, `ease-out-strong`, and `prefers-reduced-motion` is already handled by the global override.
- **Card hover is a border colour change and nothing else.** A grid of cards is hovered constantly, which puts it in the "reduce or remove" tier — the earlier version stacked a 4px lift, a border, a shadow and a 500ms image zoom, so sweeping the cursor rippled the whole grid and left several cards mid-zoom. One 150ms `border-ring/60` change reads as interactive without moving anything. Press feedback (`active:scale-*`) carries the rest, and it works on touch too.
- **Text over artwork is the one place `white`/`black` are allowed** — an image scrim has to darken the photo regardless of theme (`genre-card.tsx`, `review-card.tsx`, the lightbox). Everything sitting on a themed surface uses semantic tokens, including the banner scrim, which fades to `background` so it works in light and dark. Score scales (`ratingColor`, `metacriticTone`) are the other exception, and they ship light/dark pairs; `metacriticSurfaceTone` is the variant for themed surfaces, `metacriticTone` for the dark glass chip over an image.

## Architecture

- **RAWG is an ingest source, not a read path.** `convex/rawg.ts` holds the API key and the HTTP client; only `convex/ingest.ts` calls it. Everything the UI reads comes out of the `games` / `gameLists` / `genres` tables via `convex/catalog.ts`, so a page view costs an indexed Convex query rather than an upstream fetch. RAWG is hit only by the warm crons, by a genuine cold miss, and by a stale-while-revalidate refresh that is scheduled *after* the response is sent (`ctx.scheduler.runAfter(0, …)`). Going direct from the browser would fail anyway: RAWG's `lists/*` endpoints send no CORS headers.
  - **`stripPaginationUrls` is load-bearing, not cosmetic.** RAWG echoes the request URL — API key included — back inside the `next`/`previous` fields of every paginated response. Ingest only ever projects named fields into our own shape, so the key cannot reach a client, but the strip stays as the belt to that braces. Nothing reads `next`/`previous`; pagination is driven by the `page` argument. Don't "restore" them.
  - **The endpoint allowlist is structural now, and that is the security boundary.** There is no arbitrary-endpoint proxy any more — the old `rawg.get` / `getMany` / `getPublic` actions are gone. `catalog.ensureList` takes a *key* (`popular:2`, `new-releases:1`, `upcoming:1`, `featured:3`, `genre:action:1`) that `resolveListEndpoint` maps to one fixed endpoint template, and `catalog.ensureGame` takes a slug that `isValidSlug` constrains. A caller cannot name an endpoint, so there is nothing to allowlist. `ensureList` / `ensureGame` / `ensureGenres` stay unauthenticated because server components prerender with no session; `ensureGames` and `searchRemote` write on a user's behalf and call `requireUser`. Adding a new list surface means adding a key to `resolveListEndpoint`, not widening a regex.
- **Reads are Convex queries, writes to the catalogue are actions.** `catalog.ts` exposes `list`, `gameBySlug`, `gameByRawgId`, `gamesByRawgIds`, `search` (a Convex `searchIndex`, so search never touches RAWG for anything already ingested) and `genreList` as plain reactive queries. The `ensure*` actions wrap them with the freshness check: cold → block on `internal.ingest.*` once; stale → serve what is on disk and schedule the refresh; fresh → return immediately.
- **Three data paths, on purpose.** Route-level catalogue data (dashboard, popular, new-releases, genres, game detail) is fetched in *server components* via `lib/catalog-server.ts` and prerendered — no client round-trip. Anything user-owned (library, wishlist, reviews, chat) is Convex and reactive (`useQuery` / `usePaginatedQuery`), and `lists.page` / `reviews.list` **join the game document server-side**, so a library grid or a review feed is one query with no hydration step. TanStack Query survives only as the dedup/`staleTime` wrapper around the imperative `ensure*` actions in `hooks/use-games.ts`.
- **TanStack Query is here because the `ensure*` fallbacks are Convex *actions*, not queries.** Convex `useQuery` subscribes to `query` functions, which are deterministic and cannot `fetch()` — so an ingest-on-demand call has to be an action, and actions have no subscription, no cache, and no dedup (`useAction` just hands back an imperative callable). TanStack supplies the caching, in-flight dedup, `staleTime` and loading/error state. It is deliberately *not* used for anything already stored in Convex: that data is reactive and would be strictly worse behind a polling cache. The reactive-query-plus-ensure-action pairing in `useGameSearch` is the pattern — the local `search` query paints instantly and re-renders on its own when the background ingest lands.
- **One query-key factory per source** (`gameKeys`). Never give two different `queryFn` shapes the same key — an earlier version had `useGameByName` and `useGameSearch` both keyed on `["games","search",q]`, which made them clobber each other's cache entries.
- **Game art is served off our own disk.** `convex/images.ts` stores RAWG variants in Convex file storage keyed by `(sourcePath, width)`, and `convex/http.ts` serves them at `/img/{width}/{path}` with `Cache-Control: public, max-age=31536000, immutable`. `lib/catalog-image.ts` (`catalogImage(url, width)`) rewrites a `media.rawg.io` URL to that route; `next/image` still does the format conversion, it just has a different upstream. Widths are an allowlist (`IMAGE_WIDTHS`) and paths are validated, because the route is public.
  - **The `/img/` route never writes.** On a miss it proxies the bytes from RAWG and returns them with the same immutable header — it does *not* ingest. Storage is written only by `internal.images.warm`, which `convex/ingest.ts` schedules for paths it just ingested, so disk usage is bounded by the catalogue rather than by whatever anyone requests. Don't "optimise" the miss path into a store-on-demand: that turns a public endpoint into an unbounded disk filler.
  - **Don't turn the miss into a redirect.** An earlier version 302'd to RAWG. The proxy in front of the Convex HTTP host rewrites `Cache-Control` on redirects (300s became 14400s), so clients stayed pinned to RAWG for hours after the warm had already landed.
- `library` and `wishlist` are two tables with an identical shape, selected by the `list` argument in `convex/lists.ts`.
- Auth is `@convex-dev/auth` (password + Discord + Google). `proxy.ts` (the Next 16 successor to `middleware.ts`) redirects unauthenticated users to `/` and authenticated users away from it, so `app/(main)/**` can assume a session and `app/page.tsx` can assume none. It verifies the session JWT locally against the deployment's JWKS (`jose`, keys cached per process) and checks `iss`/`aud` — **don't switch it back to `convexAuth.isAuthenticated()`**, which round-trips `fetchQuery("auth:isAuthenticated")` to Convex and cost ~350ms on *every* request, link prefetches included. The redirect is UX only; real authorization is `getAuthUserId(ctx)` inside each Convex function.
- **Cache Components is on** (`cacheComponents: true`), so every route builds as `◐` Partial Prerender: the shell is prerendered, dynamic holes stream. That is what makes navigation instant (~15ms to first paint) instead of waiting on a dynamic RSC response. `app/(main)/loading.tsx` is the route-transition shell and `app/(main)/error.tsx` catches server-fetch failures. New data access has to sit behind `<Suspense>` or it silently un-instants the route.

## Gotchas

- **`Password<DataModel>` does not typecheck under `exactOptionalPropertyTypes`.** `authTables` generates `secret?: string | undefined`, which isn't assignable to Convex's `Record<string, Value>` index signature. `convex/auth.ts` uses the un-parameterised `Password({...})` and validates the profile with Zod instead. Don't re-add the generic.
- **A Convex function that calls another function in the same module needs an explicit return type.** If a handler's *inferred* return type consumes the result of a same-module `ctx.runQuery`/`runMutation`/`runAction`, inference goes circular and TypeScript silently degrades the whole `api` object to `any`. The symptom is implicit-any errors in unrelated `components/**` files. Annotate the handler (`handler: async (ctx): Promise<T> => …`). A `returns:` validator does **not** fix it.
- Convex functions **do not read `.env.local`** — `RAWG_API_KEY`, `AUTH_DISCORD_ID`/`AUTH_DISCORD_SECRET` and `AUTH_GOOGLE_ID`/`AUTH_GOOGLE_SECRET` are set with `bunx convex env set`. `.env.local` covers only the Next/CLI side (`NEXT_PUBLIC_CONVEX_URL`, `NEXT_PUBLIC_CONVEX_SITE_URL`, `CONVEX_SELF_HOSTED_URL`, `CONVEX_SELF_HOSTED_ADMIN_KEY`).
- Deploys run `bunx convex deploy --cmd 'bun run build'` inside the `Dockerfile`, so backend functions and frontend always ship together. The admin key is passed as a BuildKit secret, never an `ARG`.
- New external image hosts need an entry in `next.config.ts` `images.remotePatterns`. The pattern for the Convex `/img/**` route is *derived* from `NEXT_PUBLIC_CONVEX_SITE_URL` at config time rather than hardcoded, since the host differs per deployment — if that var is missing at build time the pattern is skipped and every game image 400s from the optimizer.
- **Never put a declaration in `globals.css` outside a `@layer`, especially on `*`.** Unlayered CSS beats everything in `@layer utilities` regardless of specificity, so an unlayered `* { border-color: … }` silently killed *every* `border-*` colour utility in the app — `focus-visible:border-ring` drew no ring, `aria-invalid:border-destructive` no red, `border-transparent` on badges rendered as a visible neutral border, and card hover borders did nothing. It looked like the utilities were wrong; the cascade was. Put base resets in `@layer base` (that block already sets the default border colour via `@apply border-border`).
- **`--letter-spacing` is an alias we add, not a theme token.** The `tracking-*` scale in `@theme inline` is built from `calc(var(--letter-spacing) …)`, but the generated theme files only ship `--tracking-normal`. `globals.css` defines `:root { --letter-spacing: var(--tracking-normal, 0em) }` to close the gap — remove it and every `calc()` becomes invalid, so the whole tracking scale silently resolves to `normal` and `tracking-tight` does nothing.
- **Fonts load through `next/font` in `app/layout.tsx`, and only the `default` theme uses them.** `Plus_Jakarta_Sans`/`Roboto_Mono` expose `--font-jakarta-sans`/`--font-roboto-mono`, which `app/themes/default.css` feeds into `--font-sans`/`--font-mono`; `claude` and `rose` deliberately keep system stacks. Naming a font family in a theme file without loading it here means it only renders on machines that happen to have it installed.
- **`BreadcrumbSeparator` renders an `<li>`, so it must be a sibling of `BreadcrumbItem`, never a child.** Nesting them is invalid HTML and Next fails hydration on it (`<li> cannot be a descendant of <li>`). `app/(main)/layout.tsx`'s topbar maps crumbs inside a `<Fragment>` for exactly this reason.
- **Never hardcode colors.** Three themes (`default`, `claude`, `rose` in `app/themes/*.css`) are swapped by a `data-theme` attribute, on top of a light/dark class. Use the semantic Tailwind tokens (`bg-background`, `text-muted-foreground`, `border-border`, `text-destructive`).
- **Motion is lazy-loaded.** `lib/motion-provider.tsx` wraps the tree in `<LazyMotion features={domAnimation}>`, so animated components import `m` from `motion/react`, never `motion` — the eager import pulls the full bundle and react-doctor's `use-lazy-motion` will flag it. `domAnimation` has no layout or drag features; adding either means switching to `domMax`.
- `components/ui/**` is vendored registry code (shadcn + `@magicui` — see `components.json`). We own it: it's edited in place and held to the same lint gates. Re-running `bunx shadcn add …` will clobber those edits, so diff before accepting. First-party components live directly under `components/**`.
- **Theming is first-party, not `next-themes`.** `lib/theme-provider.tsx` (light/dark) and `lib/color-provider.tsx` (palette) both persist through `useLocalStorage` and animate the swap with the View Transitions API. A vendored component that imports `useTheme` from `next-themes` will silently get `undefined` — point it at `@/lib/theme-context` instead (`components/ui/sonner.tsx` is the precedent).
- **Under Cache Components, unstable values block the prerender.** `Math.random()`, `Date.now()` or an uncached `fetch` in a server component fails `next build` with `blocking-prerender-random`. Either mark it request-time with `await connection()` (`components/dashboard/featured.tsx`) or make it cacheable with `"use cache"` (`lib/catalog-server.ts` is `"use cache"` + `cacheLife("hours")`, so public game data is prerendered rather than re-queried per visitor).
- **Read `params` / `searchParams` *inside* the Suspense boundary, never in the page component.** Awaiting them at the top of the page blocks the shell and the route stops being instant. Next reports it in the dev console (`Route "/x": Next.js encountered runtime data during prerendering or a navigation`) — that is a real failure, not noise. Pass the un-awaited promise down to the suspended child instead (`app/(main)/popular/page.tsx`).
- **react-doctor reports "maintainability checks failed" when a tracked file is deleted but unstaged.** It enumerates sources via `git ls-files`, which still lists the deleted path, then can't read it; the score comes back blank and `bun run doctor` looks broken for unrelated reasons. `git add` the deletion and it passes. `--no-cache` and clearing `node_modules/.cache/react-doctor` do **not** help.
- **`@convex-dev/auth`'s middleware discards your handler's redirect when it clears tokens.** A `refreshTokens === null` result re-wraps the response in `NextResponse.next(response)`, so a request carrying `__convexAuthJWT` *without* its `__convexAuthRefreshToken` partner gets a 200 on a protected route no matter what `proxy.ts` returns. Upstream bug, not a data leak — but it will mislead you when testing the proxy by hand.
